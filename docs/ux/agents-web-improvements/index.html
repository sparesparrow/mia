    Agent Team Portal — Web UX Improvement Roadmap

    Date: 2026-06-30 Target: /agents/

    Working Assumptions

    • Primary user: technical operator / builder using AI agents to plan, review, and execute work.
    • Primary device: desktop web, with mobile as a quick-start companion for voice sessions.
    • Main job: choose the right agent, start a session, and hand context to the next agent without losing momentum.
    • Failure cost: medium. A broken or unclear voice start erodes trust in the whole agent system.

    North Star UX

    The page should feel less like a static gallery of agents and more like a mission-control surface:

    1. User sees which agents are available.
    2. User understands which agent to start with.
    3. User starts voice or text confidently.
    4. User can hand work from one agent to the next.
    5. User can diagnose configuration problems without reading logs.

    Priority Backlog

    P0 — Trust and Operability

    These improvements prevent failed starts and confusion.

    1. Agent health diagnostics panel
    2. Add a collapsible “System status” panel below the handoff panel.
    3. Pull from /api/agents/status.
    4. Show: API reachable, ElevenLabs API key configured, each agent ID configured, signed URL availability.

    5. Use user-facing statuses: Ready, Missing config, Rate limited, API offline.

    6. Unavailable-state recovery actions

    7. If an agent is missing agentId, show a small action link: “Add local dev ID”.
    8. In dev mode, open a modal that writes agent_id_orchestrator, agent_id_evaluator, or agent_id_executor to localStorage.

    9. In production, show “Contact admin” or “Open deployment docs”.

    10. Connection state timeline

    11. Replace a single status line with a small timeline after clicking Talk:
      1. Loading config
      2. Requesting signed URL
      3. Starting ElevenLabs widget
      4. Connected / failed

    12. This makes slow starts feel intentional instead of broken.

    13. Explicit session end confirmation

    14. When ending an active session, show “Session ended” and a next-step prompt:
      • “Review with Evaluator”
      • “Execute with Executor”
      • “Start over with Orchestrator”

    P1 — Handoff and Multi-Agent Workflow

    These improvements turn three separate agents into a coherent team.

    1. Handoff summary card
    2. After a session ends, display a structured summary block:
      • Goal
      • Decisions
      • Open risks
      • Proposed next agent

    3. Initially this can be manual/static until transcript capture exists.

    4. “Send to next agent” action

    5. Add primary CTAs based on active agent:
      • Orchestrator → “Send plan to Evaluator”
      • Evaluator → “Send QA notes to Executor”
      • Executor → “Send result back to Evaluator”

    6. Even before automatic context passing exists, this teaches the workflow.

    7. Task mode selector

    8. Add a compact selector above the cards:
      • Plan a task
      • Review quality
      • Execute/fix
      • Diagnose issue

    9. Selecting a mode highlights the recommended agent and changes helper copy.

    10. Agent comparison microcopy

    11. Add “Best for” bullets per card:
      • Orchestrator: ambiguous work, roadmaps, dependency planning.
      • Evaluator: QA, risk, architecture review, metrics.
      • Executor: implementation, bug fixing, deployment steps.

    P2 — Conversation Experience

    These improvements help users stay oriented during and after voice use.

    1. Transcript preview area
    2. Reserve space below the widget for transcript events when available.
    3. Show speaker labels and timestamps.

    4. Add “Copy summary” and “Copy transcript” actions.

    5. Voice readiness checklist

    6. Before first voice start, show checks:
      • Microphone permission
      • Browser support
      • Agent configured
      • Network reachable

    7. Collapse after the first successful session.

    8. Fallback text prompt

    9. If voice fails, offer a text prompt box: “Describe what you wanted to ask.”

    10. This avoids a dead end and creates future compatibility with text agents.

    11. Session timer and rate-limit awareness

    12. Show elapsed session time.
    13. If signed-url endpoint returns 429, show retry countdown.

    P3 — Visual Polish and Brand

    These improvements make the interface feel more premium and less prototype-like.

    1. Card hierarchy refinement
    2. Make agent name and role easier to scan.
    3. Move personality title below the practical “Best for” copy.

    4. Keep color accents but reduce glow intensity in light mode.

    5. Mode-aware page title

    6. Change hero copy based on task mode:

      • “Plan with Orchestrator”
      • “Verify with Evaluator”
      • “Ship with Executor”

    7. Better empty state

    8. Current placeholder should become a starter guide:

      • “Start with Orchestrator if you are unsure.”
      • “Use Evaluator before deployment.”
      • “Use Executor when you know the fix.”

    9. Consistent icons

    10. Use distinct icons for Plan, Review, Execute, Health, Handoff.
    11. Avoid using only color to distinguish agents.

    Proposed Page Structure

    1. Header

    2. Home / Team Portal / language / theme.

    3. Hero

    4. Title: “Your Agent Team”
    5. Subtitle: short value proposition.

    6. Optional task-mode selector.

    7. System status strip

    8. Small, dismissible or collapsible.

    9. Shows whether the page is ready for voice sessions.

    10. Agent cards

    11. Availability state.
    12. Practical role.
    13. Best-for bullets.

    14. Talk / Focus / Details.

    15. Handoff workflow

    16. Orchestrator → Evaluator → Executor.

    17. Add contextual next-step CTA after any session.

    18. Conversation area

    19. Widget.
    20. Connection timeline.

    21. Transcript/summary area.

    22. Diagnostics drawer

    23. Raw endpoint status, agent IDs masked, signed URL test result.
    24. Useful for the operator without exposing secrets.

    Analytics and Success Metrics

    Track events locally or through the existing telemetry pipeline:

    • agents_page_loaded
    • agents_config_loaded
    • agents_config_failed
    • agent_focus_clicked
    • agent_talk_clicked
    • agent_signed_url_success
    • agent_signed_url_failed
    • agent_widget_connected
    • agent_widget_error
    • agent_session_ended
    • agent_handoff_clicked

    Key metrics:

    • Time from page load to first successful connected session.
    • Percentage of users who can identify the correct starting agent.
    • Agent session start failure rate.
    • Language switch usage.
    • Handoff CTA usage.

    Accessibility Requirements for Next Iteration

    • Keep all controls reachable by keyboard.
    • Add a skip link to the agent cards or conversation panel.
    • Ensure status badges include text, not color alone.
    • Announce connection state timeline updates.
    • Avoid auto-moving focus when toasts appear.
    • Keep mobile buttons at least 44px high.
    • Confirm light and dark contrast ratios after visual polish.

    QA Test Matrix

    Functional

    • Page loads with API online.
    • Page loads with API offline.
    • Page loads with no agent IDs.
    • Page loads with localStorage fallback IDs.
    • Signed URL succeeds.
    • Signed URL fails and public agent ID fallback is used.
    • Signed URL returns 429 and retry copy is shown.

    Interaction

    • Mouse click Talk starts a session.
    • Clicking active Talk ends a session.
    • Esc ends a session.
    • 1, 2, 3 start correct agents.
    • T toggles theme.
    • EN/CS updates static and dynamic copy.

    Responsive

    • Desktop: three cards in one row.
    • Tablet: cards remain readable.
    • Mobile: navigation remains available; cards stack; toasts fit viewport.

    Accessibility

    • Keyboard-only full path works.
    • Screen reader announces status changes.
    • Reduced motion disables shimmer/pulse.
    • Focus indicators are visible in light and dark themes.

    Subagent Handoff Plan

    1. UX Researcher
    2. Validate whether users naturally understand Orchestrator → Evaluator → Executor.

    3. Interview operators about real failure/recovery workflows.

    4. Frontend Engineer

    5. Build diagnostics panel and task-mode selector.

    6. Add endpoint-backed health states.

    7. Accessibility Reviewer

    8. Audit keyboard order, live regions, contrast, and mobile touch targets.

    9. QA Automation Engineer

    10. Add Playwright smoke tests for loading, i18n, theme, missing config, and keyboard shortcuts.

    11. Agent Platform Engineer

    12. Define transcript/summary payload shape for future handoff automation.

    Recommended Next Sprint

    1. Build SystemStatusStrip from /api/agents/status.
    2. Add task-mode selector and “Best for” card bullets.
    3. Add connection timeline for Talk flow.
    4. Add Playwright smoke tests for the existing fixed bugs.
    5. Prototype manual SessionSummaryCard and next-agent CTA.
